# 愿景与数据模型总纲

> 本文回答一个方向性问题：**这个项目最终要长成什么样？** 它是 `architecture.md`（当前架构）的上游——架构文档描述"现在是什么"，本文描述"一切设计向什么收敛"。两者冲突时，以落地后的 `architecture.md` 为准。

---

## 一、一句话愿景

**任意频率的流式数据、任意形式的信息注入；在其上做任意粒度的聚合观测与分析。**

拆成三个能力，层层依赖：

1. **流入层**：所有输入（设备指标、主观口述、环境上下文）统一成同构的事件流，来源可插拔，频率不设上限。
2. **聚合层**：从事件流出发，用一条确定性管线派生出任意粒度的视图（秒→小时→日→周/月/季），粒度是**派生的**，不是预定义报表。
3. **消费层**：日报告、主页、趋势、临时问答都是同一套物化数据的消费者，对任何数字都能回答"它是几版真相、怎么算出来的"。

**纪律：粒度是派生的，不是采集的。** 原始数据只按设备固有频率收，任何高频视图都从低层聚合上来，不单独采集。

---

## 二、流与批的关系（总纲核心）

一句话：**流先记账，批定真相。**

「流 vs 批」是三个独立的轴，必须分开谈：

| 轴 | 流 | 批 |
|---|---|---|
| 到达节奏 | 随时可能来一条 | 周期性整批到达 |
| 处理模式 | 增量：来一条记一条 | 重算：全量重跑出视图 |
| 真值归属 | 暂记账目，可被修正 | 最终真相 |

**到达节奏与处理模式解耦**：一批数据到达时可以逐条走流式管线（批当流用）；逐条到达的数据也可以攒到夜里重算（流当批存）。真正的分界线不在数据源，而在**处理语义**上。

### 归类

- **走流（注入语义）**：主观注入（症状/饮食/情绪，当场归档）、将来接入的高频生理信号、环境与行为上下文。
- **走批（校准语义）**：佳明官方日汇总（当日真值的裁决者）、InBody/体重等低频测量、日层判读与 `golden.json`（批重算产物，永远可从事件层确定性重建）。

批数据与流式暂存冲突时，以批为准。修正不是删流数据：流数据原样保留，物化层记录「该日 truth = 官方版，来源 = batch」。

## 三、数据模型三规则

这三条是硬约束，任何新代码不得违反：

1. **事件流不可变，视图可重算。** 事件总线只有 append 与 supersede（新事件引用旧事件将其作废），没有 update/delete。
2. **真值带版本与来源。** 聚合结果不只存数值，还存「基于哪批数据、何时算的」。批校准覆盖流暂存时，旧值降级为 `superseded`，不删除。
3. **主观数据的存储分工**：`events.jsonl` 是事件流（不可变），`daily_log.jsonl` 是日层物化视图（可从事件流重推，允许"有则更新"）。两者的更新语义不同是设计使然，不得混用。

---

## 四、架构含义

- **不需要真流式基建**。本项目的数据规模下，`jsonl 事件总线 + 定时批任务 + 确定性重算管线` 就是流批一体。引入 Kafka 类组件在这个规模是伪装的复杂度。
- **与现行架构的衔接**：「写入走文件、查询走库」不变，事件总线的库侧镜像沿用三张表；raw 永远是文件（见 `architecture.md` §八「明确不做」）。
- **判读纪律不变**：粒度越细越要防噪声当信号。所有变化仍须过 `rules.json` 的 confidence 噪声门槛（见 `notes/confidence_model.md`），高频数据不豁免。

---

## 五、推进顺序

1. **事件模型统一**（schema 定稿，主观/客观同构入事件总线）——唯一"现在不改以后必痛"的部分。
2. **聚合管线**：把日层判读改造成从片段层确定性聚合而来，以 `golden.json` 做回归，保证日层结果不变。
3. **高频数据接入**：单独立项，受佳明 CN API 粒度硬约束，需先评估可行来源。
4. **查询/分析接口**：前三步稳了之后几乎是免费的。
