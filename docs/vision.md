# 愿景与数据模型总纲

> 本文回答一个方向性问题：**这个项目最终要长成什么样？** 它是 `architecture.md`（当前架构）的上游——架构文档描述"现在是什么"，本文描述"一切设计向什么收敛"。两者冲突时，以落地后的 `architecture.md` 为准。

---

## 一、一句话愿景

**任意频率的流式数据、任意形式的信息注入；在其上做任意粒度的聚合观测与分析。**

拆成三个能力，层层依赖：

1. **流入层**：所有输入（设备指标、主观口述、环境上下文）统一成同构的事件流，来源可插拔，频率不设上限。
2. **聚合层**：从事件流出发，用一条确定性管线派生出任意粒度的视图（秒→小时→日→周/月/季），粒度是**派生的**，不是预定义报表。
3. **消费层**：日报告、主页、趋势、临时问答都是同一套物化数据的消费者，对任何数字都能回答"它是几版真相、怎么算出来的"。

**纪律：粒度是派生的，不是采集的。** 原始数据只按设备固有频率收，任何高频视图都从低层聚合上来，不单独采集。

---

## 二、流与批的关系（总纲核心）

一句话：**流先记账，批定真相。**

「流 vs 批」是三个独立的轴，必须分开谈：

| 轴 | 流 | 批 |
|---|---|---|
| 到达节奏 | 随时可能来一条 | 周期性整批到达 |
| 处理模式 | 增量：来一条记一条 | 重算：全量重跑出视图 |
| 真值归属 | 暂记账目，可被修正 | 最终真相 |

**到达节奏与处理模式解耦**：一批数据到达时可以逐条走流式管线（批当流用）；逐条到达的数据也可以攒到夜里重算（流当批存）。真正的分界线不在数据源，而在**处理语义**上。

### 归类

- **走流（注入语义）**：主观注入（症状/饮食/情绪，当场归档）、将来接入的高频生理信号、环境与行为上下文。
- **走批（校准语义）**：佳明官方日汇总（当日真值的裁决者）、InBody/体重等低频测量、日层判读与 `golden.json`（批重算产物，永远可从事件层确定性重建）。

批数据与流式暂存冲突时，以批为准。修正不是删流数据：流数据原样保留，物化层记录「该日 truth = 官方版，来源 = batch」。

## 三、数据模型三规则

这三条是硬约束，任何新代码不得违反：

1. **事件流不可变，视图可重算。** 事件总线只有 append 与 supersede（新事件引用旧事件将其作废），没有 update/delete。
2. **真值带版本与来源。** 聚合结果不只存数值，还存「基于哪批数据、何时算的」。批校准覆盖流暂存时，旧值降级为 `superseded`，不删除。
3. **主观数据的存储分工**：`events.jsonl` 是事件流（不可变），`daily_log.jsonl` 是日层物化视图（可从事件流重推，允许"有则更新"）。两者的更新语义不同是设计使然，不得混用。

---

## 四、架构含义

- **不需要真流式基建**。本项目的数据规模下，`jsonl 事件总线 + 定时批任务 + 确定性重算管线` 就是流批一体。引入 Kafka 类组件在这个规模是伪装的复杂度。
- **与现行架构的衔接**：「写入走文件、查询走库」不变，事件总线的库侧镜像沿用三张表；raw 永远是文件（见 `architecture.md` §八「明确不做」）。
- **判读纪律不变**：粒度越细越要防噪声当信号。所有变化仍须过 `rules.json` 的 confidence 噪声门槛（见 `notes/confidence_model.md`），高频数据不豁免。

## 五、页面交互形态的长期愿景

**架构的终点是查询，页面的终点也是查询。** 现在前端消费的是预定义单元（六个固定尺度 × 固定指标网格），长期形态是：**页面上的任何视图都是一次对 L2/L3 的显式查询**——「自定义窗口 × 条件组合」就是查询的两个自由度。

### 两个自由度

**① 窗口自定义**：任意起点、任意长度、任意对齐（整日/整周起算，也可滚动）。现在的六个尺度是它的六个预设快捷方式，不是天花板。判读层门槛（覆盖不足不给结论、滚动窗非重叠位移差）对任意窗口同样生效——**窗口自由不等于判定自由**。

**② 条件组合**：从「看一段时间」升级为「看一类日子」。条件三类：

| 条件类 | 例子 | 数据出处 |
|---|---|---|
| 指标条件 | 睡眠 < 6h 的日子、HRV 破基线带的次日 | L1/L2 |
| 事件条件 | 熬夜日、饮酒日、主诉头疼的日子 | 事件总线（P1 后含主观） |
| 采集条件 | 采集完整的日子（排除失败日污染） | coverage/collect 四态 |

三者可 AND/OR 组合，回答现在根本无法提问的问题：「熬夜次日的静息心率，对比非熬夜次日差多少」「采集正常日的 HRV 达标率，和全量口径差多少」。

### 三条不变纪律

1. **判定永远在后端**。任意窗口/条件下，每格的红黄绿、差值、verdict 仍由 L2/L3 算好下发——「前端禁止自己比大小」从六尺度推广到任意查询，口径唯一。前端拿到的是断言和数字，不是原始序列。
2. **视图即查询，查询可保存**。一个自定义视图 = 一段可序列化的查询定义（窗口 + 条件 + 指标），存下来就是个人面板，可分享、可回放。不做「自定义报表编辑器」这种重型产物，只做查询 + 渲染。
3. **空态与归因纪律沿用**：覆盖不足标「不给结论」而不是画成未达标；na 与 no 严格分开；采集故障不画成人的行为（frontend.md 现有纪律全部继承）。

### Agent in the loop：agent + 侧边栏浏览器，不是页内对话框

页面不是终点。**同一套查询语言有两个消费端：页面（可视化）与对话（agent）**——但载体不是在页面里嵌聊天框，而是 **agent 常驻宿主，与侧边栏里的页面预览并行协作**：人看着页面，随时对侧边的 agent 说话；agent 编译查询、改写页面深链、注入事件。

这个形态不是偏好，是三条硬理由：

1. **公开站点必须保持纯只读。** 页内对话框必然要开写端点 + 页面鉴权，等于亲手拆掉「主页不开写接口」的防线（`frontend.md`）。侧边栏形态下，写入永远走本机可信的 agent，公开页面零写端点。
2. **不重复造轮子。** 对话、鉴权、记忆、工具全在宿主 agent 里；页内嵌等于在静态站里再实现一遍且更弱。
3. **职责干净。** 页面退化为纯粹的查询渲染器（stateless，URL 即视图，可分享可回放）；交互智能全在宿主侧。两者通过两个接口衔接：**深链**（agent 把查询定义编码成 URL，侧边栏页面跳转渲染）与**反向引用**（页面状态可生成一句「把当前视图交给 agent」的提示语，由人在 agent 里续问，而非页面内嵌会话）。

Agent 在环路里的动作，严格对齐 architecture §五 的边界，分三类：

| 动作 | 形态 | 约束 |
|---|---|---|
| **读** | 把「最近三次熬夜后的次日 RHR」编译成查询定义 → 走查询接口 | 只吃 assertions/units/查询结果，禁 raw；回答必须可溯源到断言 id（`verify_judgment` 的数值溯源延伸到对话） |
| **写** | 主观注入：对话即事件总线入口（症状/作息/饮食/条件标签） | 只能 append 与 supersede，不改写历史；与页面的「视图即查询」对偶——「说的每句话即事件」 |
| **判** | 不判。档位由代码定，agent 只解释、提议条件组合、组织叙述 | 划时代的红线不变：LLM 不做算术、不改档位 |

**双向环路**：正向，agent 可把任何查询编译成深链驱动侧边栏页面；反向，页面上任何卡片/矩阵格可生成「交给 agent 追问」的上下文（查询定义 + 当前单元），由人在侧边栏续问。agent 也可在异常满足断言条件时**携带证据**主动发起对话。但日内只陈述断言事实，**结论性报告仍只在 02:00 终版产生**（现有判读纪律不变，agent 入环不改变红黄绿的产生时机）。

### 与 Roadmap 的关系

P4（任意查询接口）是这节的技术前提；P1 事件化是事件条件类与对话写入的前提。P2 片段层落地后，小时级窗口（「下午的久坐块」）才可查询。**交互形态不单独排期，它跟着查询能力走**——P4 验收时同步交付第一批预设自定义视图与「自然语言 → 查询定义」的 agent 编译入口，作为两类交互面的页面验证。
