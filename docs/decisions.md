# 决策台账

> 记录**已经定下来的选择**、**否决了什么**、**为什么**。待定的单列在后半部分，标了「等谁拍」。
>
> 为什么记否决项：半年后有人（或另一个 agent）会重新提出同一个方案，没有这一栏就会重走一遍弯路。**这是 git 查不到的信息**——`git log` 只会说「改成了 A」，不会说「考虑过 B 但否决了」，所以它必须留在文件里。
>
> 但只留结论。讨论过程、定了几次、谁在哪天说了什么，都不写——那些是 `git log` 与提交信息的事（`docs/README.md` §2）。
>
> **编号是引用锚点，只增不改**：已定项从 D-01 顺延，待定项占后续号（拍板后转正），号码永不复用。

### D25 · 是否需要 `healthd/` 独立包（等 Sir）

- **问题**：`skills/` 搬完之后，引擎代码是否再抽成可 `pip install` 的独立包。
- **选项**：(a) 不抽，`skills/body-health/scripts/` 就是最终位置；(b) 抽成 `healthd/` + `pyproject.toml`，可装到别的机器。
- **判断依据**：如果这套东西确定只在这台机器跑，(a) 够用；如果要上 NAS / 换机器 / 让别人复现，(b) 才值得。
- **这一条决定后面 80% 的工作量。**

### D26 · smoke 的两处口径型假警报（等 Sir）

- **现状**：23:30 后跑「进行中当天」固定误报 2 项。
- **选项**：(a) 修断言，让它按「当天是否已收工」动态判断；(b) 在 CI 里跳过进行中当天；(c) 保持现状，靠人识别。
- **倾向**：(b)。断言不该依赖运行时刻——那是把不确定性塞进测试。

### D27 · 不可重建物的备份口令与频率（等 Sir）

- **已做**：`tools/backup_health.py`。打包 `data/reports/` + `data/logs/*.jsonl`，openssl aes-256-cbc + PBKDF2（20 万次迭代）加密，明文压缩包立即删除。

## 三、怎么加一条决策

1. 编号顺延，**写清否决了什么**，否则半年后会被重新提出。
2. 如果决策改变了口径，必须在同一次提交里更新 `references/rules.json` 或 `metrics.json`，并跑 `backtest.py diff` 把改判清单附上。
3. 待定项拍板后从第二部分移到第一部分，不要留两份。
4. **只写结论**。过程、反复、试错写在 commit message 里。
