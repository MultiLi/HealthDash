## 二、待定

### D1 · 步数的两把尺子（等 Sir）

- **现状**：`goal`（展示达标）= `steps_goal` = **10000**；`judge`（判读线）= `steps_good` = **8000**。
- **后果**：9000 步的那天，主页卡显示「未达标」，报告不吭声。用户看到的是矛盾。
- **选项**：(a) 统一成 8000；(b) 统一成 10000；(c) 保留两把尺子但主页明确标「展示线 / 判读线」。
- **倾向**：(a) 或 (c)。理由：步数在 `confidence.tier.change` 里是 `low`，本来就不做周环比判定，用两把尺子的收益抵不上理解成本。

### D2 · rollup 与历史报告 8/30 不一致（等 Sir）

- **现状**：8 天代码总评为红，历史报告全写黄。
- **选项**：(a) 规则对 → 改历史 8 份总评为红；(b) 断言给规则档、报告层可降一档但必须写 `downgrade_reason`。
- **倾向**：(b)。判定权在代码，LLM 只有解释权与有限豁免权，且豁免要留痕。(a) 违反「单一终版」纪律（要重写 8 份）。

### D3 · 是否需要 `healthd/` 独立包（等 Sir）

- **问题**：`skills/` 搬完之后，引擎代码是否再抽成可 `pip install` 的独立包。
- **选项**：(a) 不抽，`skills/body-health/scripts/` 就是最终位置；(b) 抽成 `healthd/` + `pyproject.toml`，可装到别的机器。
- **判断依据**：如果这套东西确定只在这台机器跑，(a) 够用；如果要上 NAS / 换机器 / 让别人复现，(b) 才值得。
- **这一条决定后面 80% 的工作量。**

### D4 · 搬迁窗口（等 Sir）

- **内容**：`skills/` 搬到根目录 + 13 处路径反推集中化，涉及约 9,500 行挪位 + 全链路回归。
- **约束**：必须避开 23:30 与 09:30 两个班次。需要一段不被打断的时间。
- **前置**：H1（路径集中）应先做，它零行为变化，可单独验证。

### D5 · smoke 的两处口径型假警报（等 Sir）

- **现状**：23:30 后跑「进行中当天」固定误报 2 项。另一处「9 月均准备度期望值」已于 2026-10-25 修成自洽断言。
- **选项**：(a) 修断言，让它按「当天是否已收工」动态判断；(b) 在 CI 里跳过进行中当天；(c) 保持现状，靠人识别。
- **倾向**：(b)。断言不该依赖运行时刻——那是把不确定性塞进测试。

### D6 · 三个不可重建物的备份（等 Sir）

- **问题**：`reports/`、`daily_log.jsonl`、`notes/events.jsonl` 不在 git 里，**且无法用代码重建**（LLM 叙述与主观数据不可复现）。它们现在只存在于这台机器上，没有任何备份。
- **风险**：硬盘故障 = 32 份判读 + 38 天健康事件 + 全部主观记录一起消失。
- **选项**：(a) 加密归档定期推到独立位置（对象存储 / 私有仓 release）；(b) 换一个私有仓专门存数据（与代码仓分开）；(c) 依赖 Time Machine 等系统备份。
- **倾向**：(a)。要点是**不要用同一块盘、不要放在 `$W` 里面**——放在同一个目录里的备份，在「误删整个目录」这种场景下同样会丢。
- **注意**：私密性要求高于可用性。这三样是完整的个人健康画像，任何外部位置都必须加密。

## 三、怎么加一条决策

1. 编号顺延，**写清否决了什么**，否则半年后会被重新提出。
2. 如果决策改变了口径，必须在同一次提交里更新 `references/rules.json` 或 `metrics.json`，并跑 `backtest.py diff` 把改判清单附上。
3. 待定项拍板后**从第二部分移到第一部分**，不要留两份。
